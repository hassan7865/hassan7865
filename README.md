## What I work on

### Healthcare data and interoperability

A large part of my recent work is getting clinical systems to talk to each other reliably.

That includes HL7 and FHIR gateways so organizations can exchange data across EHR environments, using standard FHIR resources and the compliance constraints that come with healthcare. I have also built lab and medical-device integrations so clinical data can be ingested automatically and kept in sync in near real time, plus pipelines that handle HL7, FHIR, and custom healthcare message formats with an emphasis on reliability and security.

Around that sits the usual backend work: REST APIs, background processing, and workflows that have to stay available when the volume of healthcare traffic is not small.

### Applied AI — RAG, LLMs, and agents

I use retrieval and language models inside products, not as demos.

Typical work: vector embeddings + LLM inference so a system can answer from real application or website content; RAG wired into existing platforms (including eCommerce and support) so unstructured data becomes something the product can use; and agent-style workflows for regulatory and compliance tasks — reading requirements, validating, monitoring, and handing off when a human should take over.

I have also shipped this as embeddable pieces: lightweight scripts that sit on external sites and still get context-aware answers from a shared pipeline.

### Backend platforms and product surfaces

On the platform side I work on multi-tenant, multi-organization systems with role-based access, real-time routing (chat, visitor tracking, message storage under concurrent load), and data processing that has to stay consistent across clients.

Frontends are part of the same work when they need to be: Next.js with SSR and routing, React / Vite / Tailwind when the UI has to stay fast, Angular where that is the product stack, and dashboards that serve more than one store or organization from one codebase.
